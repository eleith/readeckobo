# Kobo ebook sync alongside Readeck articles

Use a per-device readeckobo API endpoint to sync Readeck articles alongside
books from a Kobo-compatible service. Readeckobo forwards Kobo API requests to
the selected user's ebook service and points the initialization response's
Instapaper URL at readeckobo. Book-service URLs in initialization and later
responses pass through unchanged. Covers and ebook downloads use the absolute
URLs generated by the ebook service, so the Kobo contacts that service directly.

[Komga's Kobo sync](https://komga.org/docs/guides/kobo/) is one example.
**Real-Kobo verification of this setup is pending.** Check it on your device
before relying on it.

## Configure the ebook service

Set `public_url` to readeckobo's public HTTPS origin. For each Kobo device, set
`book_sync_url` to that user's full **Kobo API endpoint** on the ebook service,
including any authentication path. For example, with Komga:

```yaml
public_url: "https://reader.example.com"
users:
  - token: "<READECKOBO-PLAIN-DEVICE-TOKEN>"
    readeck_access_token: "<READECK-API-TOKEN>"
    book_sync_url: "https://books.example.com/kobo/<KOMGA_API_KEY>"
```

Use an ebook-service hostname that both readeckobo and the Kobo can reach. Its
initialization response should contain the literal `https://www.instapaper.com`
in its Instapaper URL or already contain the desired readeckobo URL. Go replaces
that literal in a successful initialization response with
`https://reader.example.com/instapaper-proxy/instapaper`. The service must generate
Kobo-reachable cover and download URLs because readeckobo leaves them unchanged.
Publish the ebook service separately from readeckobo if needed.

Reload readeckobo after changing `config.yaml` (for Docker Compose:
`docker-compose up -d --force-recreate readeckobo`).

## Publish readeckobo

[Cloudflare Tunnel](CLOUDFLARE.md) forwards `/booksync/` to Go with its normal
app route. With [Nginx](NGINX.md#kobo-ebook-syncing), add the `/booksync/`
location to readeckobo's public HTTPS server. The plain device token in the
route selects the matching user's `book_sync_url`; readeckobo forwards the
remaining path and query to that service. The same public hostname also serves
article requests.

Check the initialization response before changing the Kobo:

```text
https://reader.example.com/booksync/<READECKOBO-PLAIN-DEVICE-TOKEN>/v1/initialization
```

Its `instapaper_env_url` should point to readeckobo. For a service returning
`https://www.instapaper.com/api/kobo`, the resulting URL is
`https://reader.example.com/instapaper-proxy/instapaper/api/kobo`. Its
`image_host` and image templates should contain URLs reachable by the Kobo,
whether served by the ebook service or a CDN. Treat the request URL and the service API key as secrets
when sharing logs or screenshots.

## Configure the Kobo

In `.kobo/Kobo/Kobo eReader.conf`, set the per-device API endpoint:

```ini
[OneStoreServices]
api_endpoint=https://reader.example.com/booksync/<READECKOBO-PLAIN-DEVICE-TOKEN>
```

Keep the Kobo's existing `instapaper_env_url` and encrypted Instapaper
`AccessToken`. The token in `api_endpoint` is readeckobo's plain device token;
`book_sync_url` holds the ebook service's endpoint and its own credential.
Configure the ebook service to handle any Kobo Store requests you need; for
example, Komga offers Kobo Store proxying in its Server Settings.

On a real Kobo, verify initialization, library sync, covers, ebook downloads,
and Readeck articles. Check the generated service URLs and forwarding headers
for your deployment. To roll back, restore the Kobo's previous `api_endpoint`.
